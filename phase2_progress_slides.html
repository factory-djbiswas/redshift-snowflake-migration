The wedge

"Did it convert" is not "did it run correctly"

SnowConvert auto-converts ~70-80% of objects. The remaining 20-30% "convert" but fail when executed in Snowflake — today that gap is run by hand, object by object, schema by schema.

Phase 2 turns that manual loop into an automated, logged, parallel Mission.

Every recurring failure class, in one runnable demo

What SnowConvert leaves behind

  • Redshift storage clauses (DISTKEY / SORTKEY / ENCODE)
  • JSON / SUPER dot-notation (->>)
  • Procedural logic (cursors, loops, exceptions)
  • ENUM types & array columns
  • Multi-arg NVL, SYSDATE, VARCHAR(MAX)
  • Aggregate FILTER clause
  • Missing-dependency execution order
  • Null / space defaulting on load

missions/.../rules/failure_patterns.md

A reusable rule set: RS001-RS012

Each rule carries a symptom, root cause, patch template, and example object. Ordered by frequency — the Mission tries the highest-confidence rule first.

When no rule matches, the Mission escalates with full context; the resolved fix is written back as a new rule. The catalog compounds with every schema.

run_fix_rerun.md

The execute-diagnose-patch-rerun loop

  1. Ingest source + converted output; build the dependency graph
  2. Bulk-execute the clean happy path in order
  3. Capture the exact Snowflake error (object, line, code)
  4. Diagnose against the rule set; patch the script
  5. Re-run until clean, then validate against the metadata match
  6. Log every step for GxP; parallelize across BUs
Factory

validation/metadata_match.md

Closing the last gap: null / space match

Redshift defaults empty fields to a space or null. Snowflake lands them inconsistently, so ' ' != NULL breaks the otherwise-100% match.

Normalization rule (RS008)

NULLIF(TRIM(col), '')

Applied on load, re-compared, logged before → after for audit.
